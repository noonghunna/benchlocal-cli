# Verifier Fidelity Audit

This audit compares the in-process Python scorers in `benchlocal_cli/scoring/` with the vendored upstream TypeScript verifier sources under `vendor/*/lib/benchmark.ts` plus the StructOutput sandbox verifier in `vendor/StructOutput-15/verification/core.mjs`.

> If you landed here because a run failed and you suspect the verifier, read [FAILURE_TRIAGE.md](./FAILURE_TRIAGE.md) first — most `verifier_fail`s are model misses, and that doc carries the burden-of-proof policy for escalation.

## Scope

In scope: `tool_call.py`, `reason_math.py`, `instruct_follow.py`, `struct_output.py`, and `data_extract.py`.

Out of scope: sandbox-only packs (`bugfind-15`, `hermesagent-20`, `cli-40`, `aider-polyglot-30`, `humaneval-plus-30`, `lcb-v6-30`) because they either already execute an upstream verifier runtime or use separate dataset-gated answer matching.

## Deliberate deviations from upstream

Twelve of the fourteen #143 scenarios are exact ports; parity with the vendored upstream code is tested on every corpus case. Two upstream checks rejected answers their own prompt allows, so benchlocal grades those two against the prompt instead. Both are strict supersets of upstream: every answer upstream passes still passes (asserted over the parity corpus, and verified on all 942 cases of the one-off parity run). Every other constraint in both scenarios is upstream's, unchanged. Counts below are pass@1 attempt-1 answers across the 143 saved club-3090 runs.

### IF-11 — top-level outline labels

- **Prompt:** "Create an outline with exactly 3 top-level items labeled I, II, III. Each top-level item must have exactly 2 sub-items labeled a and b. …"
- **Upstream check:** a top-level item is a trimmed line matching `^(I|II|III)\.\s`, so the label needs a period *and* following text on the same line.
- **Why it was wrong:** a label standing alone on its line — `I.` followed by its sub-items, the most common outline layout — can never match (the line is trimmed, so no whitespace follows the period), and the prompt never asks for a period. Of 130 distinct saved answers, upstream passed 11; 109 failed this constraint, 81 of them with `I.` alone on its line and 18 with `I` alone.
- **What we accept now:** the numeral alone on its line with or without a period (`I`, `I.`), or followed by a period and a title (`I. Nutrition`, as upstream). A numeral followed by text without a period (`I think …`, `I Nutrition`) is still not a label: it cannot be told apart from the pronoun. Sub-item labels (`a.`/`b.`), sentence length, keyword and banned-word checks are upstream's.
- **Evidence:** 11/143 → **70/143** runs pass. 14 of the 59 new passes depend on accepting the bare numeral. A manual read of sampled new passes found each to be a correct outline per the prompt. The sampled still-failing answers break a real constraint (`eat` in a sub-item, leaked reasoning instead of an outline); across all 50 distinct still-failing answers the failed constraints are, most often, the banned words (30), a keyword count (22) and sub-item length (20). One borderline form stays failing under upstream's sub-item rule: `I. a. …` with sub-item *a* on the numeral's line.

### SO-11 — Mermaid flowchart

- **Prompt:** "Generate a Mermaid flowchart for this process: User submits a form. System validates the input. If valid, save to database and send confirmation email, then show success page. If invalid, show error message and return to form." System prompt: output only the format — no fences, no prose.
- **Upstream check:** the answer must start with `flowchart TD`; the branches must be spelled `C -- Yes -->`/`C -- No -->` or `B -->|Valid|`/`B -->|Invalid|` (those node ids); the decision must read `Valid?` or `Is input valid?`; the return must be the text `Return to form` or an edge `G --> A`/`H --> A`.
- **Why it was wrong:** it grades one textual rendering, not the process. `graph TD`, any other direction, `C -->|Yes| D`, a decision node named anything but `C`/`B`, or a loop back spelled `F --> A` all fail. **0 of 76** distinct saved answers passed.
- **What we accept now** (`scoring/mermaid_flowchart.py` parses the diagram; `struct_output_upstream._so11_process_ok` judges it): a `flowchart` or `graph` header with any direction (TB/TD/BT/RL/LR), either edge-label syntax, any node ids, and branch labels yes/no or valid/invalid. The process must hold: all six steps appear (the upstream labels or the prompt's own wording, ignoring case and articles — "User submits a form" as well as "User submits form"); a decision node branches both ways and is reached from the validation step; the valid branch reaches save, email and success; the invalid branch reaches the error message and does not reach save, email or success; and the invalid branch returns to the form — by the text "return/back to form" or by leading back to the submit step. Code fences and surrounding prose stay unparseable, as upstream.
- **Evidence:** 0/143 → **101/143** runs pass. A manual read of sampled new passes found each to be a correct flowchart of the process. The 27 distinct answers still failing: 21 fenced, 2 leaked reasoning, 1 degenerate repetition, and 3 that merge validation into the decision (`User submits form --> {Is input valid?}`) without the "System validates input" step — kept failing because the step-label checks are upstream's.

## Expected Score Movement

**InstructFollow-15 / StructOutput-15 v2.0.0 (#143):** scores can only go down, and v2 results are not comparable with v1.x. A junk answer used to score 7/15 on each pack; it now scores 0/15. `benchlocal-cli rescore` re-grades saved results with the current verifiers — across the 115 saved club-3090 runs where nothing but these fourteen scenarios changed, pass@1 moved **IF 90.5% → 83.8%** and **SO 92.5% → 74.8%**. Rescoring a May-era result can also move *other* scenarios, because it applies every verifier fix made since; compare within the ported scenarios when isolating this change.


Correct-final-answer-only ReasonMath responses that omit published checkpoints now move from fail to pass while retaining an upstream-style score around 70 and a zero trace diagnostic. DataExtract responses that only include the first eight required fields can move down because all expected fields are scored.

ToolCall scores should not shift relative to PR #31, but the fix prevents future `node tools/build-packs.js ToolCall-15` runs from reverting TC-03/07/08/15 to strict all-calls-required assertions.
